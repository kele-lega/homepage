# 基金净值实时监控 Implementation Plan

> **For Hermes:** Use subagent-driven-development skill to implement this plan task-by-task.

**Goal:** 在 `/root/homepage` 的 gethomepage 首页中增加可自定义增删基金的净值监控卡片，后端持续抓取并缓存盘中估算净值/涨幅，正式净值发布后自动替换；只显示净值和涨跌，不显示当前金额，也不发送通知。

**Architecture:** 新增独立的轻量 Python HTTP 服务 `fund-monitor`，与 Homepage 及 Caddy 同属 Docker Compose 网络。服务使用 JSON 文件保存基金代码列表和最新缓存，提供只读查询及增删 API，并由后台线程定时抓取数据。`custom.js` 注入主页卡片，调用服务 API；`custom.css` 负责与现有 iOS 风格保持一致。基金条目只由基金代码决定名称，名称由数据源自动获取。

**Tech Stack:** Python 3.12 标准库、`ThreadingHTTPServer`、JSON 持久化、Docker Compose、gethomepage `custom.js/custom.css`。

---

## 已确认需求

- 数据口径：盘中显示估算净值，交易日正式净值发布后自动替换。
- 刷新机制：后端持续抓取并缓存，页面读取缓存；页面关闭时仍继续监控。
- 自定义能力：只输入基金代码；支持增加和删除；名称自动获取。
- 入口：直接集成 homepage 主页面，不新增独立页面入口。
- 通知：只在页面显示涨跌，不做飞书或其他消息通知。
- 不显示：当前持有金额、持仓收益金额、基金份额。

## 建议的数据与接口契约

### 持久化文件

创建 `/root/homepage/fund-monitor/data/funds.json`，建议结构：

```json
{
  "funds": ["000001", "110011"],
  "updated_at": "2026-08-19T10:00:00+08:00"
}
```

创建 `/root/homepage/fund-monitor/data/cache.json` 保存最近一次成功结果，抓取失败时继续返回上次结果并携带错误状态。

### HTTP API

- `GET /api/funds`
  - 返回基金列表、名称、当前净值、涨跌幅、净值日期、数据类型（`estimate` 或 `official`）、抓取时间、数据源和错误状态。
- `POST /api/funds`
  - JSON body：`{"code":"000001"}`。
  - 校验 6 位数字、去重；加入后立即尝试抓取并返回条目。
- `DELETE /api/funds/{code}`
  - 删除指定基金代码及其缓存。
- `GET /healthz`
  - 返回服务健康状态、最近抓取时间和失败数量。

API 默认只绑定 Compose 内部网络，不直接暴露公网；浏览器端通过 Caddy/Hopage 反代路径或同源注入方案访问，避免跨域问题。实现时需根据 gethomepage 容器的可用路径选择：优先给 Caddy 增加 `/fund-monitor/*` 反代到服务，并让前端使用该同源前缀；若 Caddy 路由无法满足，则配置严格的 CORS 仅允许当前站点。

### 抓取策略

1. 每个刷新周期从基金列表读取代码，限制并发/顺序请求，避免对单一源造成压力。
2. 优先调用可返回基金实时估算和正式净值的 HTTPS 源；禁止依赖已失效的 `fundgz.1234567.com.cn/js/{code}.js`。
3. 对基金数据解析做字段校验：代码、名称、净值、涨跌幅、净值日期必须可验证；异常响应不能覆盖旧缓存。
4. 盘中数据标注 `estimate`，正式净值标注 `official`；正式净值日期更新后优先于估算数据。
5. 服务启动时先加载本地配置和缓存，后台按固定间隔刷新；默认间隔建议 60 秒，并通过环境变量可调。
6. 非交易日、闭市时段和源异常时保留最后成功值，并在前端显示“最后更新/数据状态”，避免展示空白或伪造实时数据。
7. 用户明确只要涨幅和净值，因此 API 与前端不实现金额、份额或盈亏金额字段。

## 风险、取舍与开放项

- 场外基金没有真正的盘中正式净值；“实时”只能表示估算净值和涨跌，页面必须明确显示“估算”，正式净值发布后再替换。
- 免费公开数据源可能限流、字段变化或临时不可用；必须保留旧缓存并显示数据状态，不能把失败当成 0 或伪造涨跌。
- 反向代理路径需要与 Caddy 的 Basic Auth 和 Homepage 的静态资源规则兼容；部署验证是必要步骤。
- 当前计划默认刷新间隔 60 秒、最多先按顺序抓取少量基金；后续若监控数量明显增加，再考虑限流、并发和多数据源容灾。
- 暂不实现飞书通知、涨跌阈值、历史走势图、持仓金额和份额计算，避免扩大本次功能范围。

## 验收标准

1. 首页有一个基金监控卡片，能显示基金名称、代码、净值、涨跌幅和数据状态。
2. 输入 6 位基金代码可添加，单行按钮可删除，刷新或重启后配置不丢失。
3. 后端服务独立持续运行并缓存数据，页面关闭不影响抓取。
4. 盘中估算和正式净值有明确区分，正式净值更新后不被旧估算覆盖。
5. 数据源失败时保留最后成功数据并显示异常状态，不显示误导性 0 值。
6. 不显示当前金额、份额或持仓盈亏金额。
7. Docker Compose、反向代理、测试和现有 homepage 功能均通过验证。
