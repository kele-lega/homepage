## 合并结果

原生 `/auth/signin`、NextAuth 会话、CSRF 和退出登录采用上游实现。上游密码模式只有共享密码，本地在相同页面中增加 Username 输入，并让 Credentials provider 经内网 `/internal/verify` 校验既有 bcrypt 账号。原有 `.env`、账号文件、用户名和密码不变。

`auth-service` 不再为生产登录签发旧 Cookie；保留账号管理、自助改密、管理员重置密码及身份桥接。它向 Homepage 内网 `/api/auth/session` 查询原生会话，核对账号仍存在且 credentialVersion 对应当前密码哈希。删号或改密后，该账号已有会话不能继续通过 Caddy 授权。内部验证接口需要共享密钥，公网路由不暴露它。

基金、Steam、日历仍使用原用户名隔离。Caddy 清除浏览器自带的身份头，验证会话后重新注入；日历源码补丁只向 `HOMEPAGE_CALENDAR_ORIGIN` 转发用户名。进入仪表盘后继续非阻断刷新用户日历。

重复的自定义退出登录、外网搜索联想已移除，采用上游按钮和搜索联想。农历、时钟、站内筛选、基金、Steam、账号设置、管理员角色、明暗壁纸保留；分组顺序为甲、乙、游戏、丙、丁，普通用户隐藏丁。旧 `login-page/` 保留源码供回退，不再作为 Compose 服务；旧登录地址跳转到 `/auth/signin`。

`entrypoint.sh` 不再修改编译产物。源码构建将首页改为 SSR，以便直接读取挂载配置；刷新接口保留成功响应，让原生刷新按钮重新加载页面。`zh-CN` 由上游语言别名处理，不再打中文补丁。public 仅挂载自有图片和 favicon，保留上游新版翻译和静态资源。MCP 默认关闭，Caddy 另有管理员限制。

## 更新与检查

```bash
cd /root/homepage
docker compose -f docker-compose.yml config --quiet
docker compose -f docker-compose.yml build homepage auth-service
docker compose -f docker-compose.yml up -d --no-deps --no-build homepage auth-service
docker exec caddy caddy validate --config /etc/caddy/Caddyfile
docker exec caddy caddy reload --config /etc/caddy/Caddyfile
```

Homepage 构建内运行 78 项上游及适配测试，再编译生产镜像，测试文件不进入页面路由。独立服务测试为认证 15、基金 67、日历 18、Steam 20，共 120 项。升级已在独立 Docker 网络和测试数据目录完成真实浏览器登录、错误密码、退出、跨账号数据隔离、账号新增/改密/删除，以及手机和明暗主题检查。

生产验证使用短期原生测试会话做只读检查，不改真实账号密码或数据。首次升级后需重新登录。旧 `/auth/login`、`/auth/logout` 在生产返回 410；新流程使用 `/api/auth/*`，不要复用旧 Cookie。

再次升级上游时，同步更新 Dockerfile 的源码提交、校验和、版本和上游镜像，`apply-patches.mjs` 的版本断言及兼容逻辑，还有 Compose 的本地镜像标签。先在隔离环境验证再切换；不要直接把镜像改回 `latest`。
